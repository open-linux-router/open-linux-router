# Temporary device request inspection

The device detail page shows DNS queries separately from HTTP(S) requests. A DNS lookup is not proof of a visit. The DNS list is a recent network-wide sample matched to the device's current IPs; the relay's query log must be enabled.

Request inspection is opt-in and temporary. Install `mitmproxy` (`mitmdump`) on the Linux router before starting. On Debian, use `sudo apt install mitmproxy`. It is not a package dependency because it is only needed for debugging. OLR starts its own transparent mitmdump instance and creates a debugging CA in `/var/lib/open-linux-router/inspection` (directory mode 0700). Back up or remove this directory only with the implications for devices that trust its CA in mind. The API exposes only the public PEM, never the private key.

1. Open a device's detail page, confirm or edit the source IPv4 address, and start a 15-minute inspection. The first session generates the CA.
2. Download the public CA from the page, or show its QR code and scan the public-certificate link from a phone on a network that can reach the router. The link needs no admin token and serves only the public certificate. Install it **on that device** as a trusted root certificate for HTTPS. On iPhone, after installing the profile, enable full trust in Settings > General > About > Certificate Trust Settings. Compare the certificate's SHA-256 fingerprint to the value on this page; if they differ, remove the old profile and install the current public CA. Never bypass the Safari warning for an unverified CA. There is no proxy address to configure.
3. Browse from that device. HTTP requests need no CA; HTTPS requests appear only if the app accepts the user CA. Stop and clear when finished, and remove the CA from the device's trust store. Stopping interception does **not** revoke trust on the device.

Only one session and one explicitly chosen source IPv4 address are inspected at a time. The device list suggests an address, but OLR does not verify its MAC ownership or track address changes. If the address is wrong or reassigned during a session, traffic from another device may be intercepted. Confirm the address before starting and stop when finished. IPv6 traffic is not intercepted. OLR redirects only TCP 80/443 to public destinations; UDP/443 (QUIC), local/LAN destinations, IPv6, other ports and non-HTTP protocols are not inspected. OLR does not block UDP/443 to force fallback. When the selected device has an explicit gateway exit, OLR marks only mitmdump's locally generated upstream packets to follow that exit (for example, Clash) so fake-IP DNS answers remain usable and inspectable. This process-group-scoped rule is installed and removed with the session. With no explicit exit, fake-IP destinations (`198.18.0.0/15`) still bypass interception rather than leak toward the router's default uplink. Do not change the device's exit during an active inspection session; stop and restart inspection to pick up the new exit. Certificate pinning and apps with separate trust stores may fail to connect or remain uninspected. The page does not claim a complete connections list.

During a session the page shows redirect-rule packet and proxy-accepted connection totals. They are diagnostics, not a complete connections list: the redirect counter counts packets matching the IPv4 TCP rule, while the proxy counter counts accepted sockets. A zero redirect count after an IPv4 HTTP test means the rule did not match; a growing redirect count with zero proxy accepts points to delivery between netfilter and mitmdump. Neither count proves that an HTTP response completed.

The listener input guard accepts only the selected IPv4 source when conntrack records an original TCP destination port of 80/443; direct connections to the proxy port from the LAN are dropped. A redirect is not reliably identified by `ct status dnat`, so do not use that bit for this guard.

The proxy must be ready before nftables interception is installed. OLR removes its own nftables table at stop/timeout/proxy exit and before startup, and restores normal forwarding on failure. The session holds at most 200 request/failure events in daemon memory, including headers and up to 4,096 characters of text response preview per event. Binary and responses larger than 1 MiB are not previewed; mitmdump streams large bodies. Nothing is persisted and all events clear on stop. Treat URLs, headers and previews as sensitive. CA trust and the CA key remain after a session; a future rotation workflow should coordinate removing trust from devices.

Validation on a real Linux router is required before relying on this in production: test HTTP and trusted HTTPS, an untrusted/pinned app, IPv4 address changes, QUIC, proxy crash, daemon restart and nft cleanup failure. macOS Go/UI tests cannot exercise the netfilter path.
